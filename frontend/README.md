# TypeForge 学习工作台

本目录已经包含可构建的 React + TypeScript 客户端。页面使用真实会话、CSRF 和业务 API，学习记录、作答、错题块、作品版本、导师请求与后台导出均由服务端确认。当前实现范围与最终验收状态应结合仓库首页、`contracts/openapi.json` 和实际测试报告阅读。

## 运行

推荐 Node.js 24；最低要求为 Node.js 22.12。依赖已精确锁定，使用 `npm ci` 安装。

```bash
cd frontend
npm ci
npm run dev
```

开发服务器默认为 `http://127.0.0.1:5173`。Vite 将 `/api` 代理至 `http://127.0.0.1:8080`，会话与 CSRF 使用同源请求。另一个终端在仓库根目录启动后端：

```bash
mvn -f backend/pom.xml spring-boot:run -Dspring-boot.run.profiles=demo
```

`demo` 提供原创、代码复核的演示课程内容；它不代表正式双人内容审核。自行注册账号后创建工作空间。没有内置公开密码。

```bash
cd frontend
npm run check
npm run build
```

`check` 执行 TypeScript 检查与 Vitest 测试，`build` 生成 `dist/`。后端构建将该目录打包为静态资源；采用 `#learn`、`#practice`、`#studio/<id>` 等 hash 路由，不需要将未知 API 路径回退到 HTML。打包顺序是前端构建后再执行 Maven，具体 CI 与发布命令以仓库根目录配置为准。

## 按页面加载与构建容量

作品、内容编辑、学习创作、检索评测及管理员运行状态使用 `React.lazy`，首次进入页面时再读取对应脚本；加载期间保留工作台结构并提供就近等待状态。没有新增前端依赖。v0.6 的最终生产构建记录如下，单位为 Vite 输出的十进制 kB：

| 构建部分 | 文件大小 | gzip 大小 |
|---|---:|---:|
| 首屏主 JavaScript | 354.28 kB | 109.95 kB |
| 主样式 | 76.77 kB | 15.24 kB |
| 作品与活动笔记页面 | 66.03 kB | 20.74 kB |
| 内容编辑与批量加工页面 | 50.79 kB | 14.97 kB |
| 检索评测页面 | 29.04 kB | 9.28 kB |
| 学习创作任务页面 | 14.11 kB | 5.65 kB |
| 运行状态页面 | 6.99 kB | 2.83 kB |

相同 v0.6 功能在拆分前的主脚本为 518.29 kB／gzip 154.75 kB，拆分后首屏 gzip 下降约 29%。这表示构建传输容量，不是实测弱网首屏时间或生产性能 SLO；共享小图标块和运行状态的独立样式仍按实际依赖加载。数字由 `npm run build` 产生，完整构建结果与来源摘要以验证报告为准。

## 状态与安全边界

- 会话凭据由 HttpOnly cookie 承载。CSRF 从服务端取得，登录轮换会话后重新获取；密码不进入浏览器存储。
- 工作空间组件按 ID 重建；读取使用 `AbortController`，异步提交用 generation 校验，旧响应不能写入新工作空间界面。
- 工作空间事件按 `after` 游标轮询；重放去重、发现序号缺口时不推进游标。重新挂载从零分批重放，服务端 GET 仍是资源事实来源。当前没有 SSE。
- 任务轮询等上一次读取结束再安排下一次；隐藏或离线时暂停，失败按上限退避。写请求有界超时、同步防重入，结果不明保留幂等键与输入，由用户明确重试。
- 幂等写操作将输入摘要与请求键保留到服务端确认，网络结果不明时重试复用原键。导师和证据工作流的中间快照也保留，防止重试创建另一项任务。
- 文档与幻灯片草稿按账号、工作空间和作品保存于本标签页存储。后台事件不覆盖脏稿；遇到新版本必须比较后明确选择。当前没有自动合并或“另存为副本”流程。
- 作品内容、引用和基线拒绝迟到的旧版本回填；保存期间暂时禁用编辑和基线操作，失败后保留输入并恢复编辑。显示偏好按当前账号和revision单调更新，连续保存使用服务端返回的新版本；退出清除旧账号的主题监听。
- 预览使用固定 React 元素，来源文本只作为文本。没有 `dangerouslySetInnerHTML`、`eval`、任意脚本、模型选择组件导入或任意 HTML 执行。
- 导出只有 `SUCCEEDED`、`sourceState=CURRENT` 且下载路径属于当前导出任务时显示下载。失败、失效、被替代或损坏的源不会被显示为可下载。
- 作答、暂停、取消、记忆撤回、保存和偏好设置都等待服务端确认；HTTP 202 表示任务已接受，不表示内容已完成或已审核。
- 新活动的动作同时携带源稿修订、区块修订与交互状态修订。首次状态未确认前禁用写入；冲突保留输入并要求重新读取基线。同题族对照只接受来源允许的真实题目，关联作品只使用服务端返回并复核的私人版本。
- 评测集冲突明确区分服务端版本与本地样例；更新保存基线需要确认，不覆盖本地标注。历史运行继续指向原来的数据集修订与语料哈希。批量导入完成或取消后预览正文清除，界面使用真实终态及保留的采集 ID。

详细状态边界见 [state-contract.json](state-contract.json)。OpenAPI 是网络字段的权威来源；本目录的 TypeScript 类型是针对页面实际消费字段的手工映射，不宣称自动生成。

## 验证分层

单元测试覆盖 CSRF 轮换、网络结果不明与截断成功响应时复用幂等键、真实文件字节指纹、旧 workspace 响应隔离、迟到的旧会话 401/CSRF 隔离、事件去重与缺口、非重叠轮询、同步重复点击、草稿冲突与迟到读取、保存中编辑保护、内容多来源与独立草稿、审核协议、代码题异步判分、账户改密、幻灯片键盘边界、偏好连续保存及账号切换、中文输入法 Enter、安全预览。v0.6 增加 TEXT 原文提交与私有规则、概念路径、导入冲突与终态、评测基线和取消、Notebook 状态 CAS 与逐题草稿／提示、旧块动作许可、写入类型方向以及运营权限撤回。

当前类型检查、60 项组件测试与生产构建已通过；新增的代码修复对照用例验证两份任务结果独立显示、等待期间保护源码、完成后修改明确标记过期结果，而且不会把编译成功显示为已判分。真实 HTTP 的 DOM 场景已在最终干净构建的 v0.6 JAR 上完成 24 条链路，运行前后源码与 JAR 摘要保持一致，最新 driver 报告摘要与运行记录绑定。准确摘要见 `test-results/dom-runtime-report.json`；图形 Chromium 仍以本次远端运行事实为准。

真实 HTTP 的 DOM 联调（不是图形浏览器）在启动真实 demo jar 后，挂载实际 React 页面并执行注册、错答、错题复练、文档保存与导出、并发写冲突、导师转文档、撤回来源、个人资料和趋势、真实 PNG 上传与带图片的幻灯片、Office / PDF 文件字节、学习创作任务、空间隔离和退出清理。响应、判分、来源与文件字节均来自后端；cookie 和 multipart 传输适配器仅连接 DOM 与 Node fetch。

v0.6 的 `tests/workbench-journey.mjs` 由真实 DOM 与 Chromium 驱动共享同一条可见业务流程：作者上传实际 Markdown／DOCX 与损坏文件、构建前置知识、修订比较、编辑 TEXT 与同题族变式，第二位编辑独立审核发布，学习者阅读与复练、追加 Notebook 活动、运行两个不同 K 的真实检索评测并下载报告，最后由管理员读取实际聚合统计。各步骤的 PASS / FAIL 以本次报告为准，不能用脚本存在代替执行成功。

jsdom 31 在 `user-event` 选择文件后，其原生 `required` 校验仍读取内部空文件列表。DOM 驱动先逐字节核对所选文件，再只适配这一已复现的校验差异；服务端容量、解析和提交均不绕过。真实 Chromium 保留原生文件校验。DOM 报告只有完整流程抵达末尾才会 PASS，浏览器脚本的场景外异常也记录失败并以非零退出。

```bash
# 仓库根目录；先构建完整 jar
python3 scripts/browser_runtime.py \
  --jar backend/target/typeforge-backend-0.6.0-SNAPSHOT.jar --driver dom
```

真实浏览器测试使用 Playwright 自带 Chromium，默认不选择系统 Chromium：

```bash
cd frontend
npx playwright install --with-deps chromium
cd ..
python3 scripts/browser_runtime.py \
  --jar backend/target/typeforge-backend-0.6.0-SNAPSHOT.jar --driver browser
```

如已有服务，可设置 `TYPEFORGE_BASE_URL` 后执行 `npm run test:e2e` 或 `npm run test:live`；新编辑链还需提供测试专用、已注册并授权的两个 EDITOR 与一个 ADMIN 身份，环境变量为 `TYPEFORGE_TEST_EDITOR_AUTHOR`、`TYPEFORGE_TEST_EDITOR_REVIEWER`、`TYPEFORGE_TEST_ADMIN_USERNAME` 和 `TYPEFORGE_TEST_EDITOR_PASSWORD`。请使用隔离测试库，不把真实运营账户交给验收脚本。`CHROMIUM_EXECUTABLE_PATH` 只用于明确选择已有的兼容 Chromium。

`browser_runtime.py` 使用隔离 H2、随机本地端口、就绪检查、有界超时和退出清理。它通过真实注册接口建立随机账户，再重启同一个隔离数据库，通过正式 operator bootstrap 配置两个编辑和一个管理员；不写入后门角色或直接 SQL。测试密码不放在后端命令行或报告中。失败保留非零退出码与日志，不转换为跳过。第二位测试账户完成的审核是自动化权限验收，不声称为人工教学审核。

报告输出到 `frontend/test-results/`：

- `browser-report.json`：真实浏览器步骤、页面异常与控制台异常；成功执行时保存业务步骤截图、各已启用学习页面在 1440 / 390 / 320 像素视口的截图、菜单焦点与溢出检查结果。
- `live-dom-report.json`：真实 HTTP 的 DOM 联调步骤与限制。
- `browser-runtime-report.json` / `dom-runtime-report.json` 与对应 server log：真实 jar 的启动和清理结果。

本地受管环境的 Chromium 曾在打开页面前因 `socket() failed: Operation not permitted` 被阻止；Browser 插件也没有可用的 originating connection。**这不是浏览器通过记录。** 图形布局、真实移动视口、原生下载和浏览器控制台以实际 CI 浏览器报告为准。DOM 验证与单元测试不能替代这项验收。

## 视觉与参考真实性

界面采用“纸面阅读＋代码实验”的方向：中性浅色表面、青绿色动作、安静导航、可读的规则与真实代码。暗色主题、键盘焦点、44px 控件目标、原生表单、减少动效与 IME 提交保护已写入实现，完整的视觉与辅助技术验收需以真实浏览器检查为准。

`reference-ledger.csv` 保留全部 209 项的研究与取舍记录。当前界面为业务导向的原创实现，**没有把 209 项演示全部运行、高保真复刻或授权审核的说法**；未复制 React Bits 源码，也没有安装整个动效库。具体落点见 [交互实现与参考边界](interaction-implementation.md)。

设计检查采用 unslop 方法（Damir Sokolovsky，@heydamir，CC BY 4.0），用于方向、间距、颜色、文字、布局与动效顺序审查；没有复制该技能的图像或组件资产。图标来自锁定版本的 Lucide React，依赖许可保留在各 npm 包中。
