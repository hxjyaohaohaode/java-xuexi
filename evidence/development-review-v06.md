接续基线为 main `0e9d1bce53e96bdd0e84fe0d5d8a55bf59fd3bec`。本轮继续实现真实业务，而非仅重复上一版命令。16 个模块的当前范围和剩余项见[模块指南](../docs/02-modules.md)，新增数据链见[实现说明](../docs/24-evaluation-import-and-notebook.md)。本文记录发现与决策；最终测试数量、构建 SHA-256 和源码摘要由[机器报告](runtime-check-results.json)记录，远端 Docker/Chromium 由精确提交的 Actions 证明。

## 第二轮：独立复核与失败修复

1. **上传并发限制过晚。** 原实现先读取最多 4 MiB，再争抢解析许可；高并发可能在被拒绝前占用内存。现许可覆盖读取、hash、解析、持久化整个请求。两个阻塞输入流占满时，第三请求必须在 `getInputStream()` 之前返回繁忙；异常和正常退出均释放许可。
2. **DOCX 主体可能重复。** `AlternateContent` 的 Choice/Fallback 都含文本时，普通递归读取会把两份都导入。现明确拒绝并指引另存文本；第三位独立审查者又用真实解析重现 moveFrom/moveTo 导致已移动文字被导入两遍，现对未处理的修订/移动容器受控拒绝并加入回归。严格内容类型 XML、DTD/实体、ZIP 部件、路径、压缩率、深度、字符和实际 POI 文档分别测试。
3. **评测部分结果占用漏算。** 只计完成报告不足以限制取消/失败历史。现中间结果、完整报告和准入预留共同纳入账户上限，逐案例/累计字节均验证；报告额外明确 suite ID/revision 并复验元信息。
4. **轮询与下一案例提交竞态。** 读到 completedCases 后下一案例可能提交；现仅读取已公布的不可变前缀，避免正常进度增长被误判为 hash 冲突。
5. **旧错题块语义兼容。** 旧 TYPE_FLOW 的 `T` 参数和动作不能直接按新版命名候选解析。保留旧配置，新增严格 BoundedTypeFlowConfig；新动作只显示在被实际准入的块上。
6. **合法长题与来源数量。** 旧错题 prompt 8,000 小于题目允许的 16,000，16概念×2卡还会超过引用限制。现完整保留题面，优先采用原题独立审核的精确知识引用；旧 demo 每概念最多一张回退。
7. **切换变式串用提示级别。** 以当前本人、空间、精确题目/版本的真实回执恢复最高提示；切换不会借界面清零辅助记录，也不会把上一题提示展示成下一题。
8. **运维看不到新增任务。** 增加评测运行/失败、有效/过期待清理导入、真实 UTF-8 JSON/正文占用；管理员权限撤销立即拒绝，页面隐藏此前快照。空直方图返回 null，不展示虚构的 0 ms。
9. **测试上下文调度相互干扰。** 同一真实 MySQL JVM 的多个 Spring 上下文可能同时领取手动测试队列。共享 test profile 关闭评测自动调度并延长预览清理间隔；服务用例显式推进，独立进程 HTTP/浏览器仍使用实际生产调度节奏。
10. **前端缺少真实变式编写入口。** 原编辑器只能新题族或修订同题，导致已有反事实 API 无法从页面闭合。新增从实际题目派生同题族新题，保留独立 ID/审核和发布步骤；不以测试专用 API 代替使用流程。
11. **浏览器门禁可能漏记外层异常。** 原外层捕获只记录控制台错误，而退出状态依赖逐项 failures；新增流程在逐项检查外失败时可能留下空失败集。现外层异常必须补失败项，DOM 报告还要求完整走到终点。集成启动器检查两次启动前及结束后的 JAR hash，一次运行不能混入不同构建。
12. **验收摘要可能接纳旧报告。** 原汇总仅核对 PASS、JAR 和现存 Surefire，无法证明源文件未在测试后改动。改为各门禁记录实际受检输入摘要，干净构建还核对完整测试集合与 JAR；汇总拒绝过期输入、缺失用例或混用构建，并以反向回归检验守卫。

13. **真实停机的数据库关闭竞态。** 增强后的 H2 重启流程已完成新评测和 Notebook 数据恢复，却在最后日志检查发现后台 outbox 读取遇到 H2 `90135`：H2 自身 JVM 退出钩子早于 Spring 容器收尾关闭数据库。默认、测试和两个独立进程验收的 H2 URL 加入 `DB_CLOSE_ON_EXIT=FALSE`，按 [Spring Boot 3.5 官方说明](https://docs.spring.io/spring-boot/3.5/reference/data/sql.html)由容器控制关闭顺序；保留后台错误零豁免门禁，重新干净构建与重启验证。

定向测试分别覆盖真实 SQL/session、反向权限、版本冲突、idempotency、并发互斥、原子回滚和来源撤回。协议夹具、固定 javac、真实 Docker 和浏览器证据分别标识。

## 第三轮：组合回归与交付门禁

最终干净构建通过 **455 项 Java 测试**，失败、错误、跳过均为 0；前端 **60 项组件测试、类型检查与生产构建**通过。同一个最终 JAR 的 **24 条 DOM + 真实 HTTP 链**全部通过，包含作者、独立审核者、学习者和管理员；运行前后源码与 JAR 摘要一致，步骤报告为本次新生成文件。

原生 **MySQL 8.4.13 的14条迁移、88张表、195项约束检查**通过。服务回归为事务隔离 **2项**、审核发布 **15项**、账户/素材 **22项**、新增业务 **75项**，均核对实际数据库引擎、当前测试集合和执行前后输入摘要。新增服务早期一次为74/75：数据库正确拒绝伪造完成状态，但MySQL CHECK的3819/HY000被Spring分类为UncategorizedSQLException；测试改为严格核对实际错误码/SQLState和拒绝后的原记录，没有削弱约束，随后整组重跑通过。

独立进程 HTTP/重启在 H2 通过 **93项**、MySQL 通过 **108项**。新增比较包括评测套件/固定运行/真实 JSON 附件字节、Notebook新修订/状态/实验回执和另一账户的404隔离；探索与评测前后学习掌握证据必须不变。修复H2停机竞态后，在三份独立文件库上连续执行同一最终包，每次93项且两次实际启动/停机，所有后台日志均无未预期错误；[三次原始计数与摘要](h2-shutdown-regression.json)保留结果，不把重复检查冒充新的独立用例。

离线编译 broker **13项**、验证脚本反向门禁 **20项**通过。静态检查数量、全部用例名称、当前输入清单与最终JAR摘要由机器报告生成。图形Chromium和真实Docker编译由发布后该精确提交的Actions独立运行，不能用上述DOM或协议夹具替代。

浏览器测试使用三名每次随机的隔离账户：先真实注册为 LEARNER，正常停机，再对同一验证库以正式启动配置授予两个 EDITOR 和一个 ADMIN，随后真实登录。它不依赖 SQL 升权、绕过会话或生产凭据；自动独立审核仅是测试夹具，不能记为两位真实学生的人工贡献。

对初次请求、正常完成、服务失败、冲突保稿、取消、旧版本/来源失效、重新加载、小屏、键盘和减少动态分别核对。失败修复后只重跑受到影响的范围；最终构建冻结后再跑整套门禁并记录精确字节摘要。
