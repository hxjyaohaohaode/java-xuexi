## 教学语义核查

甲的示例专家正确写出了直接赋值不成立，并用“假如允许赋值，就可以通过 Number 列表别名加入 Double，破坏原整数列表的约束”完成反证。两个概念角色的讲解相近，分工有重复。模型规划倾向 concept-first，成品前六页仍保持学生选择的 example-first 顺序。乙的规划模型获准使用复练角色，但实际选择了三个示例角色。两位专家提交的文字完全相同。专家虽然正确否定了赋值，仍称“List<Number> 的类型参数发生变化”，也没有解释上界通配符在新题中的作用。两个声明在编译期有不同的具体类型实参，判断赋值时实参不会动态改变。两份作品均为 DRAFT。

在这个例子中，`Integer` 是 `Number` 的子类型，但这层子类型关系不能自动提升为两个具体参数化 List 之间的赋值关系。题目问的是 Java 编译期类型检查。样例恰好使用 `List.of`；解释别名写入为何破坏类型约束，应将其作为对允许可变列表赋值的反证，不应说此私有草稿真的运行过写入。[Java SE 17 语言规范 §4.10](https://docs.oracle.com/javase/specs/jls/se17/html/jls-4.html#jls-4.10)
