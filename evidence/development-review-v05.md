# v0.5 三轮开发与审查记录

本轮从 `60f5a836f7afb64f908a367403ea2307d85a70d5` 的 main 接续。旧任务工作目录没有可恢复的未提交改动，因此以可核对的仓库内容为基线，补全真实业务链并保留已有版本/权限/证据边界。

这里记录审查范围、发现与修复；最终通过数量、源码摘要和实际命令结果由 [runtime-check-results.json](runtime-check-results.json) 与 [runtime-review.md](runtime-review.md) 给出。三轮是不同层次的检查，不是把同一命令重复三次。

## 第二轮：实际集成、异常路径与独立交叉审阅

本轮使用独立复核者审查其他模块，结合真实数据库和 HTTP 协议测试。以下是实际发现并修复的问题，而非泛泛的检查清单。

| 发现 | 修复与回归依据 |
|---|---|
| 账户关闭后同名新注册可能受旧用户名授权影响 | 特权名称保留；审计查历史授权；真实会话主体绑定 userId/auth epoch，不能把旧请求映射到同名新账号 |
| `no-store` 被后续过滤器覆盖；阅读只留活动而缺乏持久状态 | 缓存头组合修复，阅读索引与回填、跨设备读取 |
| UTC 趋势聚合依赖服务器本地时区 | 明确 UTC 起止时间分桶，在非 UTC 午夜条件验证 |
| 提示 action 被旧数据库 CHECK 拒绝，导致整笔事务回滚 | 新增前向迁移放行 requestHint/requestCompile，保留旧迁移与历史回执；真实 MySQL 验证 |
| 编译超时未统一取消；空 classpath 触发严格编译参数失败 | deadline/取消统一、实际创建只读空 classpath、固定 JDK 源码编译回归 |
| 不配对 Unicode 源码、转义诊断可能漏过协议检查 | 入队前拒绝非法源码；解析后检查诊断敏感内容 |
| 内容审核使用 APPROVE/REJECT，与后端 APPROVED/REJECTED 不符 | 对齐严格枚举；重新验证独立审核与发布链 |
| 修订知识只保留首条来源，题目丢误区标签 | 完整保留来源与 misconceptions；每份表单独立草稿、覆盖前明确确认 |
| 保存任何一个表单会清空整个工作台的未保存标记 | 单独管理表单状态，保存只清对应草稿；请求期间锁定当前输入 |
| 设置页读取最新 revision 后会用旧输入覆盖新值 | 固定编辑基线，冲突保留原稿并明确重新读取选择 |
| 慢网轮询不断取消前一个尚未完成的请求 | 读取结束后才安排下一次，隐藏/离线暂停、失败退避 |
| 学习调用 execution key 超过导师幂等长度 | 在保持确定映射的前提下使用服务端 SHA-256 标识 |
| UNKNOWN 状态后继续 fail 导致同事务回滚 | 先持久保留未知用量与 WAITING_USER，后续只能对账，不能自动当零费用重试 |
| 长问题挤掉审阅者实际看到的专家答案 | 按实际正文和用户修订提取，保留定长分工配额与当前来源 |
| 用户编辑规划稿后重排可能复用旧分工、重跑规划 | 应用前验证规划输出仍有效，否则暂停；不把修改后计划混入旧图 |
| 长期未知历史任务可能饿死新任务 | 活跃工作和历史对账分批、公平轮转 |
| 笔记直到任务末尾才发现选中了独立正确作答 | 在入口确认错误/辅助且已判分；明确保存选择，不静默扩张 |
| 本地渲染占用事务，取消/修改可能被迟到文件覆盖 | 事务外渲染、短领取/提交事务、租约与最终来源校验；并发测试实际取消和修改 |
| DOCX/PDF/HTML 仍使用创建时旧标题 | 固定源稿 DSL 的当前修订标题统一驱动实际正文和元信息 |
| 重复图片可造成大字符串/反复解码，缓存无账户上限 | 增量输出上限、HTML 重复字节预检、PDF 图片复用、图像像素总量、账户缓存/日任务限制和过时缓存回收 |
| MySQL 的 DATETIME 通过通用 Map 读取时与 H2 返回类型不同，导出提交强转失败 | 租约改用明确的 `ResultSet.getTimestamp` 行映射；用实际 MySQL HTTP 导出与重启链验证，不能只依赖 H2 |
| 重复运行真实 MySQL 测试时，MockHttpSession 从数字 1 重新编号并撞上旧会话 hash | 测试会话使用每次随机命名空间，继续真实改密登录、会话轮换与 CSRF；保留生产唯一约束和旧数据库记录，复跑编辑/账户/素材门禁 |
| 首次远端 Docker 检查发现 `-Werror` 的全局诊断未被识别为编译错误 | 根据真实 javac 17.0.21 输出支持 `- compiler.err.*` 前缀；增加精确输出回归，并确保未知非零退出仍为基础设施失败；不放宽八项容器验收 |
| 真实 Chromium 功能检查通过，但截图中窄屏概念表仍把中文挤成逐字竖排 | 为证据表设置可读列宽、可聚焦的局部横向滚动区和提示；复习标题允许整行换位；新增 320/390 像素列宽、方向键滚动、末列操作可达和标题布局断言 |
| 已实现的提示接口没有登记 `EXERCISE_HINTS`，前端入口因此被隐藏；错题集看完第三级仍提示继续读取 | 将确定性的分级提示登记为不依赖模型或编译 worker 的内置能力；前端 18 个能力标识逐一与后端注册对照；验证真实三级提示、受助成绩与错题集完成态，失败不得推进提示级别 |
| `/framework` 的实际 phase 与 OpenAPI 常量不一致，旧测试只检查模块数量 | 对齐当前阶段 `connected-learning-studio`；使用真实响应执行 schema 校验，防止元信息接口绕过契约检查 |

模型路径使用真正的 loopback HTTP 协议夹具驱动规划、专家、审阅和作品，不使用伪造“外部供应商通过”声明。代码语义使用固定仓库源码和完整 JDK。真实用户代码隔离需独立 Docker worker，图形浏览器布局需真正 Chromium，二者均独立报告。
