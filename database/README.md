# 数据库与迁移

当前为 v0.6，V001–V014 累积 88 张领域表，不含 Flyway 元数据表。完整字段与约束以 [data-dictionary.md](data-dictionary.md) 为唯一入口，由所有前向迁移累积生成；不再维护互相容易漂移的分版本字典。

|---|---|

| V002 | 工作空间、目标、事件、上下文、持久任务、作品、素材、导出和记忆 |
| V003 | 作答归属、家族独立证据、投影、传递来源索引、本地证据工作流、outbox 重试 |

| V005 | 手工采集、知识采集关联、题目知识关联、独立审核完整哈希、发布清单与编辑锁 |

MySQL Profile 执行原始 SQL；H2 Java migration 基于同一 SQL 适配引擎声明、类型和约束元数据，没有另写一套简化业务结构。V008/V011 替换旧 CHECK 时分别查询真实数据库元数据，不假设 MySQL 与 H2 自动生成的约束名称相同。业务控制服务使用 READ_COMMITTED 和显式行锁，避免先读后等锁继续读取 MySQL 旧快照。身份、空间与资源归属检查在应用层完成。

V001–V014 是当前完整升级链，已应用的迁移不删除、不回写。后续从 V015 继续追加；新增非空列需要明确旧数据回填策略，约束变更必须在真实 MySQL 验证。不要在现有 Flyway 库上手工运行所有 SQL，也不要通过清空 schema history 掩盖迁移不一致。

## 测试数据与真实内容

`seed-demo.sql` 仅用于独立 SQL 完整性检查：禁用作者、来源、概念、草稿卡与草稿 release，没有激活发布。正式应用的演示数据由显式 `demo` Profile 从 `knowledge/runtime-lessons.json` 初始化。两者都是测试/演示入口，不能作为已完成双人审核的正式课程。

正式内容由 M07/M10 HTTP 工作台记录真实编辑身份、来源和采集文本。作者不能自审；审核保存完整内容哈希；release 冻结概念图与知识/题目版本。发布指针使用 expectedActiveRevision，重试不会把后来已改变的活动发布改回旧值。旧工作空间固定原 release，历史成绩不会被新版本覆盖。

## 验证

```sh
python scripts/sync_contract_index.py --check
python scripts/verify.py
python scripts/verify_mysql.py
```

MySQL 检查默认创建专用 Docker 容器，测试后只清理自己创建的容器。已有隔离验证服务器可通过脚本定义的私有配置接入；不能指向生产库。当前模式检查覆盖 V001–V014 完整升级链和全部领域表；账户/素材、内容发布及新增评测/导入/TEXT/Notebook 服务分别有真实 MySQL 事务回归。具体表数、用例数及通过情况由实际报告生成，避免手工重复统计漂移。最终环境、结果、HTTP 重启和隔离级别证据见[当前验收](../evidence/runtime-review.md)，H2 不替代这些结果。

账户关闭已经实现跨领域撤回、会话失效、未完成队列取消和上传/导出缓存字节清理，保留历史学习与发布审计；普通用户名可复用但数据始终绑定原 UUID，特权用户名保持保留。完整个人数据物理擦除、统一保留期清理、备份自动化和生产容量验收仍需专项工作。相关边界见[数据与隐私](../docs/03-data.md)及[账户与素材](../docs/22-account-assets-operations.md)。
