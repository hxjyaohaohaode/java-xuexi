# 按学生兴趣上课，在课内完成练习

本章以同学提交的「泛型与类型安全」为教学边界，覆盖 G01–G16。打开一个知识点，在「调整兴趣与要求」里填写想研究的情境和希望怎样学习。例如，两位学生都学 G06。一人希望分析篮球队名单，先预测再动手；另一人希望从天文观测星表出发，解释编译反例并设计变式。两人仍需掌握同一条 Java 类型规则，可以通过相同课程版本的正式题比较学习结果。

## 同一节 G06 的实测与修正

第一轮在 GitHub 的真实模型任务中，篮球学生和天文学生各有两份专家初稿用到了各自的领域词。两人的总用量分别是 6,079 和 6,129 token，包含输入与输出。四个审阅动作却全部选择了类型推导。由此发现，只把“请预测”或“给我反例与迁移题”放进模型上下文，学生最终拿到的活动仍可能相同。本轮新增验收会直接检查成品中是否包含本人明确要求的活动，并分别记录学生指定的活动和模型可自行选择的活动。[首轮 GitHub 模型任务](https://github.com/hxjyaohaohaode/java-xuexi/actions/runs/45979634992/job/140445833366)

真实 Docker 课堂在浏览器中运行了带标准输入的 Java 与 Python、同学的原始类型警告案例，以及课件生成的完整 Java 预测题。篮球题的错误写入先返回编译失败，学生把写入对象改成正确的类型后成功运行。返回题面时，课堂保留了判断和题目草稿，独立实验的未提交编辑也保留。工作进程回执报告的工具链为 javac 17.0.21.1 和 Python 3.10.12。[浏览器与隔离工作进程实测](https://github.com/hxjyaohaohaode/java-xuexi/actions/runs/45979634992/job/140439943666)

修正后的双学生回放在 12,288 token 上下文的本地 Qwen3-0.6B 上执行。每位学生有两名专家，审阅者实际收到了二者的草稿。篮球课生成 13 页，生效的是学生指定的「编译预测」和审阅者在三个可选活动中选择的「类型推导」。天文课生成 12 页，指定的「对照反例」和「迁移练习」都进入成品，迁移页要求学生具体比较写入端的 `List<? super Transit>`。两位学生的供应商输入和输出总量分别为 6,204 与 6,203 token；四次专家调用实际输出 209–266 token，每次分配到的输出上限为 6,088–6,144。已核对的 792 个打包应用类和资源与完整验收构建逐项相同。GitHub 工作流以 16,384 token 的窗口独立执行同一组验收。[实际题目、活动来源、模型用量及成品摘要](../evidence/interest-led-classroom-model.json)
