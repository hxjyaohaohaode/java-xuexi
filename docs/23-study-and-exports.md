# 教学工作流与作品导出

本页记录已经有执行代码和回归测试的范围。运行状态由数据库、执行回执与当前引用决定，页面不会把一个等待动画或已生成的 JSON 当作完成。

## 从目标到作品

`POST /workspaces/{id}/agent-runs` 接受当前目标、固定上下文、明确选择的 DOCUMENT / SLIDES / NOTEBOOK、时间与 Token 上限、EVIDENCE_ONLY 或 MODEL 模式。目标必须包含在快照中；别人空间或过期引用不能入队。每个空间最多三个未完成任务。

EVIDENCE_ONLY 使用确定性课程证据整理。MODEL 需要配置实际导师 HTTP 服务：规划者返回有限 JSON，选择 1–3 个 CONCEPT、EXAMPLE、REPAIR 分工；每项通过独立、持久导师请求执行，然后再发起一次审阅请求。规划失败、证据不足、超时、未知用量均有真实终态或等待状态。

这些是有限、可追踪的分工，不是任意执行工具的通用自主系统。专家和审阅者可能使用同一配置模型，审阅不是独立人工核验，作品均保持 DRAFT。

| 阶段 | 实际行为 | 版本和边界 |
|---|---|---|
| 规划 | 验证策略与 1–3 项教学重点 | 不能从模型文本获得工具/权限；用户改过的规划不会被旧计划覆盖 |
| 分工 | 复用导师检索、上下文、配额和请求队列 | 每次请求绑定可核对的工具执行标识；无未知调用自动重发 |
| 审阅 | 固定当前专家稿作为待审材料 | 从已接受的专家修订读取答案；后续修订使旧复核失效 |
| 整理 | 生成独立文稿、幻灯片或复练笔记 | 不覆盖已有修订；事实引用及传递血缘保留 |
| 使用 | 在 Studio 中编辑、预览、导出 | 编辑采用基线版本比较，冲突保留本地草稿 |

`POST /workspaces/{id}/notebooks` 复用同一执行链，接受明确选择的 1–8 个错误或辅助作答。创建时即检查所选作答的本人、空间、课程、判分状态和快照包含关系，避免花费模型用量后才发现无法生成。`POST /workspaces/{id}/context` 可带 `{ "attemptIds": [...] }`，把较早的所选作答加入快照；不传时仍默认取最近 8 次。

### 教室内分工和来源交接

本地规划选择 2–3 项真实工作。目标明确要求先举例时，先派发示例设计；其他新概念先派发规则解释。快照中有错误或受助的本人作答时，先安排代码纠错，使用选中的作答与实际得分。每个步骤按获准的学习重点重新检索课程，模板中的“请制定计划”等指令不参与相关性排名。有适配题目时示例设计使用已发布的题干，否则给出构造反例的练习。

当下游角色接受工作时，`agent_message` 在同一数据库事务中记录双方角色、计划版本、执行代次、依赖步骤及源版本摘要。规划→专家的 QUESTION 表示分派，专家→审阅的 PROPOSAL 表示草稿，审阅→组装的 VERDICT 表示审阅意见。每个已接收项目通过 `GET /agent-runs/{id}/study` 的 `handoffs` 显示。相同代次的重复领取复用收据，旧代次可供追溯。审阅快照只继承原始快照和已成功交接的草稿。之后创建的目标或记忆不进入本次审阅。证据模式的审阅逐稿核对知识引用的标识、版本与摘要；语义正确性仍需要实际作答、代码或人工审核佐证。

`GET /workspaces/{id}/learning-path` 按所属空间和固定课程计算顺序，优先安排纠错，其次给已读未练的概念分配练习，再按前置关系安排阅读。在同优先级内优先显式命名的目标和它的前置概念。练习优先选未接触的题目家族；阅读与重复练习均不产生独立掌握样本。课堂导出可以把当前章节的课程证据和前三项建议交给 [DeepSeek Harness 工具](../integrations/dsh-classroom/README.md)。

### 暂停、取消、恢复

暂停和取消增加 run epoch，撤销正在等待的导师请求。已确认的实际用量进入账本；无法确认的外部调用保留预留，进入 WAITING_USER。未知用量没有被伪装为零费用。

恢复以新 epoch 执行，旧请求和工具回执仍保留。租约过期后先对账，再由用户恢复。计划重排保留历史和已确认用量，不重置时间上限。公平轮转把活跃执行与历史对账分批，长期 UNKNOWN 不会挡住所有新任务。

Token 与时间上限有效。当前没有配置模型价格表，`maxCostMicros` 在通用账本中存在，但此适配器不会估算供应商账单，也不构成供应商金额上限。实际费用需以供应商回执/账单核对。

## 原生文件

文档使用 Apache POI 生成可编辑 DOCX，使用 PDFBox 生成内嵌中文字体、可搜索的 PDF。幻灯片支持 PPTX、PDF 和 HTML，实际嵌入已授权 PNG/JPEG；PPTX 文字/代码可编辑，讲稿和知识引用进入备注。每次渲染使用固定 DSL 修订中的标题、内容和位置。

图片按原始比例放入用户指定区域。画布外坐标、无法容纳的文本、缺失或撤回素材、非法 XML 控制字符、PDF 字体没有的字符会返回可处理的错误。不会静默裁掉整段文字或省略图片并宣布成功。

渲染不会执行源稿中的 HTML/JavaScript，不拉取任意外部 URL。HTML 图片以 data URL 内嵌，CSP 仅允许自身样式及 data 图片。私有下载需要当前账号权限；SHA-256 对精确文件字节计算。

### 资源与取消

| 项目 | 限制及处理 |
|---|---|
| 单文件输出 | 8 MiB，写入流实时限额 |
| 文稿 PDF | 最多 80 页 |
| 幻灯片图像 | 独立输入总计 8 MiB、总分辨率 32 MP；重复 HTML 图片事先按重复字节检查 |
| 本地渲染 | 两个固定工作线程；PDF 相同图片复用对象 |
| 账户导出 | 同时最多 8 个排队/运行作业；24 小时最多 200 个新作业 |
| 缓存 | 账户最多 256 MiB；同版本/格式复用，过期源稿缓存回收，任务元信息保留 |
| 运行租约 | 120 秒，过期明确失败；不伪造可下载文件 |
| 取消 | 阻止迟到提交与下载；本地库渲染可能完成当前计算，不等于立即打断 CPU 指令 |

渲染在数据库事务外执行，领取和结果提交使用短事务。提交和下载都重新检查当前源稿、素材、祖先引用与租约。渲染期间修改源稿或撤回素材，旧文件不会成为新的可下载结果。

## 验证入口

- `StudyWorkflowIntegrationTest`：真实持久任务、检索、草稿、文件、幂等、暂停/恢复、取消、租约与来源变化。
- `StudyModelWorkflowTest`：真正 loopback HTTP 协议服务驱动规划/专家/审阅；无效规划、未知用量、预算不足和迟到返回。它不是外部供应商质量评测。
- `WorkspaceContextSelectionTest`：较早作答的明确选择、HTTP 兼容、归属和未判分限制。
- `ArtifactFileExportTest`：重新打开实际 DOCX/PPTX/PDF，检查中文字、字体、图片、备注、修改后标题；取消/源稿变化竞态、重复图片容量和缓存回收。
- `PrivateAssetsIntegrationTest`：真实文件识别、越权、配额、Range、撤回和关闭账户后的字节删除。

生成式图片、TTS、任意时间线视频渲染、离线运行交互题、任意 Java 程序执行和真实外部模型的教学评估仍需独立实现或部署验收；不会用一张静态预览或模拟数据代替它们。
