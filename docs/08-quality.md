# 质量、安全、验收与运行

## 1. 当前与最终的检查边界

v0.4 的验证覆盖当前路由与契约、固定 javac 语义、SQL 事务、身份和编辑角色、学习投影、来源闭包、导师队列及本地 HTTP 协议夹具、内容审核发布、真实文本导出、前端组件和真实后端操作。实际命令、结果、环境和未验证限制只以 [当前验收](../evidence/runtime-review.md)为准；旧版本报告保留在 Git 历史。前端 209 条台账仍是参考研究记录，不能视为 209 个已运行组件。真实供应商教学质量、沙箱隔离、完整媒体、生产负载与备份恢复仍需专项实测。

## 3. 必须连通的系统级场景

1. 新用户登录 → 阅读不变性 → 做预测题 → 编译反例 → 查看知识引用 → 保存一次提交 → 查看本人进度。
2. PECS 题失败 → 请求一级提示 → 只看到概念提示 → 修改代码 → 正反向测试通过 → 错题复练记录出现；提示后结果不冒充独立掌握。
3. A 发布新知识版本 → B 打开旧会话 → 旧引用仍可定位；新学习入口使用新版本；未就绪索引不切指针。
4. 双击提交/断网重发 → 一次判分与一次学习投影；同 key 不同源码得到 409。
5. worker 执行中崩溃 → 租约超时 → 有限重试 → 旧 worker 回来被 token 拒收 → 不发生重复判分。
6. 模型超时 → 清晰显示导师不可用 → 知识检索/客观练习继续 → 不把错误当作已完成提示。
7. 甲把乙的 attemptId/conversationId/jobId 发给 API → 404；甲的 UI 也不能通过缓存看到乙的数据。
8. SQL 备份恢复 + 发布索引恢复 → 固定题目版本、引用与学习记录一致；重建投影不重复加分。
9. 小屏/触屏/键盘/减少动效完成同一主链路；进入/退出实验 30 次无事件重复触发与明显内存增长。
10. 教师随机点一个题/答案 → 可追溯来源、版本、编译核验、作者/复核、真实改动与测试。

## 4. 威胁与质量控制

| 风险 | 设计控制 | 必须实际验证的点 |
|---|---|---|
| 不可信源码与编译输入 | 独立 worker、无凭据、禁网、资源/时间/输出上限 | 进程组销毁、宿主不可读、OOM/超时行为 |
| 越权与答案泄露 | 对象归属检查、角色、公共 DTO 无答案 | 每个 ID 参数独立的双用户负例 |
| 注入与 XSS | 参数化 SQL、受控 Markdown、URL allowlist、工具白名单 | SQL/HTML/prompt 注入样本 |
| 重复请求和重复事件 | 幂等 key+请求hash、outbox、receipt 同事务 | 并发提交与重放一致性 |
| 错误的泛型讲解 | 规范、独立复核、javac 正反例、warning检查 | 不把AI结果当事实 |
| 发布不一致 | 不可变版本、索引READY、事务指针 | 发布/回退与旧会话测试 |
| 大模型延迟/花费 | 请求/工具/token预算、取消、失败降级 | 真实 API 费用和限额 |
| 过度动效 | 按需组件、焦点语义、减少动效、离屏暂停 | 真实设备与性能记录 |
| 依赖/供应链 | 固定版本/锁文件、许可证、漏洞检查 | 正式部署前扫描，不宣称本基线已完成安全认证 |

## 5. 性能和稳定性指标（目标，未实测）

明确测试环境、样本量和版本后报告 p50/p95/p99、错误率、资源峰值。100 虚拟学习者条件下普通查询 p95<300ms、检索 p95<500ms；编译排队/执行和模型首响应/总耗时分别统计。重试次数、队列上限、超时和拒绝率不能隐藏。MySQL 慢查询用 EXPLAIN 与真实数据优化，禁止以增加缓存掩盖错误权限键。

恢复目标起点：进程重启后已提交成绩不丢；worker 故障在租约窗口内恢复；通过已验证备份恢复可重建发布/学习投影。具体 RTO/RPO 在部署环境明确后实测记录，不提前填写“零丢失、秒恢复”。

## 6. 可复现命令

```sh
python -m pip install -r requirements-dev.txt
python scripts/sync_contract_index.py --check
python scripts/verify.py
npm --prefix frontend ci
npm --prefix frontend run check
npm --prefix frontend run build
mvn -B -ntp -f backend/pom.xml clean verify
python scripts/verify_mysql.py
python scripts/smoke_runtime.py --profile h2
# 已安装 Playwright Chromium 后，运行真实浏览器集成：
python scripts/browser_runtime.py --jar backend/target/typeforge-backend-0.4.0-SNAPSHOT.jar
```

没有本地 JDK/Maven 时，在仓库根目录用容器（PowerShell）构建：

```powershell
docker run --rm --mount "type=bind,source=$((Get-Location).Path),target=/workspace" --workdir /workspace maven:3.9-eclipse-temurin-17 mvn -B -ntp -f backend/pom.xml clean verify
```

启动命令与 Profile 详见 [后端说明](../backend/README.md)：`mvn -f backend/pom.xml spring-boot:run -Dspring-boot.run.profiles=demo` 可启用演示课程。数据库迁移/连接、会话/CSRF 和部分业务 API 已实现；注册后登录并重新取 CSRF 才能使用受保护接口。正式部署仍需 TLS/安全 cookie、真实 MySQL 环境校验、限流与日志/备份、独立 worker、模型/媒体适配和完整前端；当前整体仍为 `businessReady=false`。

## 7. 发布阻断规则

P0 缺陷：知识或判分严重错误、越权、密钥泄露、用户代码逃逸、数据丢失、主链路不可完成。P1：版本混用、重复加分、无法恢复、主要键盘路径缺失。最终提交前 P0/P1 必须关闭；低优先级缺陷写清影响与回避。框架提交允许未实现功能，前提是显式 planned 且不伪造验收结果。

## 8. 集群系统级验收

1. 三错题→专家计划→共享事实→互动册/PPT/微课→学生新变式独立作答，完整保留run/context/goal/release/artifact/attempt关联。
2. 编辑PPT一页时改变讲解结论，只有相关旁白/镜头/错题解释过期；改颜色不重新检索/编译。
3. 暂停后旧worker回调、用户手工编辑与Agent回写同时发生；验证epoch、lease、baseRevision，不能丢用户改动。
4. 同事件重复投递、同工具返回重复通知、同资源写入竞争；验证只结算一次、只提交一个版本、所有消费者可重放。
5. 图片/TTS/视频供应商分别中断、结果未知、限额耗尽；已完成作品保留，状态/费用准确，不进入无限重试。
6. 私人素材夹带指令或恶意嵌入链接；不得突破工具范围、文件网络边界或读取其他学习者。
7. 用户撤回记忆/切换空间/切换发布；新调用不带旧空间或撤回上下文，正在运行的任务需要重新核验引用。
8. 八类作品的源结构可编辑，导出能打开/播放；六类错题块的每个action有真实后端结果，键盘/触屏也完成同任务。
9. 完整30案例分别测单Agent、固定多Agent、动态编排；相同材料、模型/预算/时间条件，报告成功率和失败，不用生成字数证明智能。

集群目标值须在固定模型、硬件、预算、样本条件下设定与实测。基础50例教学评测和30例集群对照评测是不同维度，不能相互替代；现有16/30案例只是未运行的起始设计。媒体生成耗时与普通查询性能分开记录，不能拿2核4GiB查询测试环境承诺高并发视频渲染。

需求→模块→接口→表→当前检查→后续验收的逐项映射见 [traceability.csv](../evidence/traceability.csv)。当前实现的权限测试不等于未来全部接口均已覆盖；本轮范围不包含真实模型效果、恶意代码沙箱、媒体制作/导出、生产压测或浏览器 UI 验收。最终课程验收另见 [交付说明](16-course-delivery.md)与[需求矩阵](../evidence/course-acceptance-matrix.csv)。
