# 两人开发计划、贡献与最终成果

最终课程验收采用 [交付说明](16-course-delivery.md) 与 [40项需求验收矩阵](../evidence/course-acceptance-matrix.csv)。本章的 A/B 为职责标签，尚未绑定真实姓名或贡献；阶段表是完整工作组织，不是整阶段完成声明。v0.6 已落实学习、编译、账户、内容控制台、有限专家任务、私有素材及原生 Office/PDF 导出链；生成媒体、正式内容人工审核和真实供应商效果仍需完成。实际实现和测试以 [本轮验收记录](../evidence/runtime-review.md)及 [contracts](../contracts/README.md) 为准；不能把助手协助实现的代码自动记为某位成员已完成贡献。

v0.6 新增有界 TXT/MD/DOCX 批量资料加工、知识/题目修订对比、独立审核的 TEXT 精确判分、六类可恢复错题交互、私有检索评测和管理员运行指标，并将概念前置关系接入学习页面。具体边界、容量和联动见[本轮实现](24-evaluation-import-and-notebook.md)。

## 1. 分工原则

用户已确认教师认可两人组，两人都能承担复杂开发；不按能力高低分工。A/B 可以交换，但应在第一轮开发前绑定真实姓名/GitHub 账号。项目负责人由两人选定，负责整合与进度，不自动获得另一人的贡献。

| 研发链路 | A 主责 | B 主责 | 交叉协作 |
|---|---|---|---|
| 知识与智能 | M02/M07/M08/M09/M10 | 提供编译 oracle 与判分事实 | B 审核知识正反例/引用；A 审核编译解释 |
| 实验与学习 | 提供概念、误区与评测 | M01/M03/M04/M05/M06/M12 | A 测试越权/异常；B 测试检索降级 |
| 集群与作品 | M13编排、M15上下文/记忆 | M14多模态创作、M16交互错题 | A验证作品事实门禁；B验证任务并发/恢复 |
| 前端 | 工作空间壳、目标/运行面板、阅读、检索、指导、内容工作台 | 文档/PPT/音视频画布、动态错题、实验、练习、身份设置 | 共同维护tokens/导航/DTO；各自完成对应端到端页面 |
| 数据库 | 内容/发布/检索/对话、workspace/goal/context/run/step/memory | 用户/编译/判分/记录、artifact/asset/export/notebook | schema变更互审；outbox、lease和跨域事务共同确认 |
| 过程与答辩 | 知识/检索/Agent 讲解与记录 | 类型工具/系统工程讲解与记录 | M11、需求、集成、全系统测试共同完成 |

不将前端全部交给一人、知识资料全部交给另一人。每个人都有复杂算法/工程模块、页面、数据库、测试与独立答辩材料。工作量以任务完成和技术解释衡量，不比较提交次数或代码行数。

## 2. 阶段顺序（以工作阶段计，不虚构截止日期）

| 阶段 | A | B | 合并门禁 |
|---|---|---|---|
| S0 架构与运行时认领 | 审阅知识/Agent/上下文实现与契约 | 审阅认证/判分/作品实现与契约 | 复现 v0.6，认领真实后续工作，核对限制 |
| S1 数据与基本链路 | 16 概念扩为可发布内容，确定检索 corpus | 会话、迁移、题目/提交实体与权限 | 实际 MySQL、登录、读取知识、保存提交贯通 |
| S2 编译与检索 | BM25、来源预览、检索 gold set | 隔离 worker、错误结构、客观判分 | 真实编译 + 真实检索，不依赖模型 |
| S3 工作空间与专家闭环 | 模型适配、真实RAG、目标/快照、计划/预算/租约、分级提示 | 类型实验、学习记录、Notebook/Document/Slides DSL与画布 | 三错题→任务图→互动册/PPT→独立复练；支持中断/冲突 |
| S4 完整多模态 | 模型路由、个性化记忆、专家分工/门禁与局部重规划 | 图片/图解、分段音频、视频时间线、PPTX/DOCX/PDF等导出 | 各媒介真实可用，可继续编辑并保留证据；供应商失败可部分交付 |
| S5 深度内容与可靠性 | 全量知识审核、发布回退、单/多/动态Agent对照评测 | 八类实验、反向类型测试、媒体质量、并发与故障恢复 | P1全范围覆盖；两人交叉review；费用/耗时/失败真实记录 |
| S6 验收与展示 | 知识/集群/工作空间及真实对话材料 | 编译/创作/交互/部署及数据库材料 | 八类成果、全系统回归、实机演示、互相模拟答辩 |

每一阶段都有可运行成果，不等全部后端完成再拼前端；每周或每个阶段结束以任务完成情况重新平衡两人的负载。已经落地的认证、SQL 读取、BM25、编译判分、工作空间/事件、作品源版本和持久任务控制应复用并继续验收，不重新当作空白项目。现有前端、导师适配器、审核发布、私有素材和文件导出可继续扩展；真实供应商质量、目标部署环境隔离验收、正式内容人工复核和完整生成媒体仍需完成。任何接口变化同步更新 OpenAPI、DTO、SQL/映射及消费者测试。

## 3. Git 协作

从 main 拉短分支，例如 `feat/knowledge-retrieval`、`feat/compile-worker`。变更尽量围绕一条可验证链路。对方 review 后合并；不可因 AI 生成就略过理解和检查。公开仓库不得包含个人学号、账号口令、API Key、私人聊天、原始敏感学习记录。

提交说明写“解决什么问题、行为怎么改变、如何验证”；研发日志写失败原因和修复，不只堆成功截图。AI 协助生成的本次基线应如实标注，后续两人分别理解、修改和验证。不要把一次 AI 生成的初始 commit 当作两个人真实完成全部模块的证据。

## 5. 最终产品的 12 分钟答辩目标

下列脚本面向最终产品，涉及沙箱、PPTX和音视频的部分须完成后才能演示；当前版本可演示路径见根README。

0–1分钟共同介绍课程知识点与工作空间；1–3分钟B演示PECS预测、真实编译与错误证据；3–5分钟A提出“三错题→互动册+PPT+微课”，展示真实任务图、检索引用和专家分工；5–7分钟B操作错题集与PPT，定位证据并局部修改；7–9分钟A展示目标变更、上下文接续、取消旧节点与预算；9–10.5分钟B展示实际视频/音频、复练结果与版本传播；10.5–12分钟共同展示故障恢复、对照评测、贡献和限制。耗时媒体可用有完整真实运行轨迹的预生成产物，并明确标注，不能冒充现场即时生成。

必备问题：为什么List不协变；为什么extends不是不可变；为何super读出Object；捕获helper和桥接方法做什么；`AgentTool<I,O>`如何维持组合类型且为何仍需JSON校验；客观成绩为何不由模型决定；DAG怎样调度与裁剪；如何防重复消费/越权/迟到worker；作品依赖怎样传播；为什么集群优于单Agent必须实测而非数头像。

## 6. 项目完成定义

全功能真实可操作、数据库与知识库有实际内容、真实模型已验证、主要异常可恢复、两人都理解关键实现、八类资料完整、干净环境可复现、演示不依赖伪数据替代生产功能。当前 v0.6 已贯通当前契约的业务链，但不等于最终完成定义。优先按 [模块接手指南](02-modules.md)认领真实模型评测、编译服务部署与资源验证、通用自治、完整生成媒体与内容扩充。16 卡/12 题演示内容不自动变成正式双人审核课程；具备审核发布 API 也不等于真人已经审完全部课程。

## 7. 每人需要独立保留的证据链

| 证据 | A主责示例 | B主责示例 | 交叉检验 |
|---|---|---|---|
| 问题与设计取舍 | 知识卡与检索证据为何必须绑定release；短问答与集群路由 | 编译失败与评分失败如何区分；作品修改怎样保护学生编辑 | 对方复述约束并提出一个失败场景 |
| 本人实现与修改 | 检索/上下文/计划其中一条完整真实链路 | 实验/判分/作品其中一条完整真实链路 | 对方运行并记录实际结果 |
| 独立解决的问题 | 引用失效、记忆撤回、任务超预算、模型失效 | 并发保存、重复作答、worker迟到、导出失败 | 保留原因、修改和复测，不只保留成功截图 |
| 全系统理解 | 从学生输入追踪到证据与作品 | 从复练追踪到学习投影与下次Agent上下文 | 各自能画同一链路并解释权限与事务边界 |
| AI协作记录 | 指出哪些建议采用、拒绝或改写及验证理由 | 指出哪些生成代码需修复及测试证据 | 不把助手生成基线当成两人已独立完成 |

每个合并项记录需求ID、实现范围、证据与未完成部分。评价基于实际任务、技术掌握与协作贡献，不以提交次数互相比较。原始课程材料和私有对话不为凑证据公开上传；只公开必要、经过脱敏的项目过程。
