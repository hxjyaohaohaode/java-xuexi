# 教学专家能力、RAG 与局部评测

## 1. v0.6 已实现的服务边界

M09 现在有真实持久会话、异步请求、取消和回答转文档链路。会话固定在本人的工作空间及课程发布版本；每次提问明确选择 `snapshotId`、`mode` 与 `hintLevel`。Java 服务执行检索与回答流程，没有让模型决定成绩、发布知识、读取他人记录或运行系统命令。M04 已有独立编译与诊断协议；导师自主调用任意工具仍未开放。新增学习任务复用同一持久请求/额度，完成有限规划、专家回答、独立复核与作品组装，详见 [学习任务](23-study-and-exports.md)。

| 模式 | 实际执行 | 明确限制 |
|---|---|---|
| `EVIDENCE_ONLY` | 本地 BM25 检索已发布知识，按学习分工整理原始片段、可核对引用及下一步问题 | 普通提问按 0–4 级选择学习提示，原始引文保留原文；未调用语言模型 |
| `MODEL` | 显式配置 endpoint/model/key 后，通过真实 HTTP Chat Completions JSON 协议调用供应商 | 未配置时创建请求返回 503；本地协议夹具不等于真实供应商兼容性或模型教学质量已验证 |

`TUTOR_EVIDENCE_ONLY` 与条件启用的 `TUTOR_MODEL` 分别反映上述能力。`EvidenceWorkflow` 仍是另一个入口：它通过持久 DAG 调用 `retrieveContext`、`searchEvidence` 两个真实 `AgentTool<I,O>`，只产生证据，不产生 LLM 教学答案。导师请求采用自己的持久队列、租约、epoch 与额度，没有冒充十四个专家的自动协作。

实际模型端口是 [`TutorAnswerProvider`](../backend/src/main/java/io/typeforge/tutor/TutorAnswerProvider.java)，HTTP 实现及生效系统提示在 [`HttpTutorModelProvider`](../backend/src/main/java/io/typeforge/tutor/HttpTutorModelProvider.java)。`agent/system-prompt.md` 与 `agent/conductor-prompt.md` 是教学原则和未来设计参考，不会被当前请求自动加载。实际能力以 [契约](../contracts/README.md) 为准；启动和配置见 [后端说明](../backend/README.md)。

## 2. 当前持久请求、额度与作品链

1. 身份来自服务器会话，写接口要求 CSRF。问题最多 4000 字符，提示级别 0–4；会话、空间、固定发布及快照归属必须一致。可选 `attemptId` 必须是该快照中的本人已判分提交。同一幂等键重放同一请求，换参数返回冲突，不重复计额度。
2. 在 user → workspace → request 的短事务锁序内记录请求、绝对截止时间、UTC 日额度及 outbox。worker 有界领取，外部 HTTP 不占数据库事务或公共定时调度线程。
3. 以问题的前 500 字符检索固定 release，最多取 4 条真实证据。所有快照引用和证据重新检查归属、revision/hash、撤回与发布状态。无命中直接进入 `INSUFFICIENT_EVIDENCE`，不调用模型或编造答案。
4. MODEL 发出前固定配置指纹并记录“已派发”标记。外部响应先经严格 JSON 与引用门禁，再在短事务中复检 epoch、lease、deadline、完整快照和证据。只允许引用本次准入的 1–4 个不同知识片段；不接受重复 key、尾随 JSON、截断、额外回答字段、伪造/重复引用或已知凭据回显。供应商返回 `answer/citedChunkIds/limitations`，完整 `TutorResult` 由服务端生成。
5. 回答、引用、供应商自报用量、实际返回模型标识和终态事件持久保存。读取请求或历史时也复检来源；来源失效则返回 `sourceState=STALE`、`answer=null` 和空引用，保留历史请求状态用于解释。引用身份与版本校验不等于证明模型每句话正确，结果附带未独立事实/编译核验说明。
6. 用户显式调用 `/tutor/requests/{id}/document`，才能把本人 `COMPLETED` 且来源有效的回答保存成 `DOCUMENT/DRAFT`。内容注明模式、请求 ID 和未人工核验；快照全部来源与实际引用一起去重保存，同源版本冲突拒绝，超过 64 个来源返回 422，不丢依赖。作品、版本、来源链接及幂等记录原子提交；记忆撤回、目标修改和作品换版后的失效链继续生效。后续人工编辑与受支持文件导出复用现有作品流程，不能由模型直接写为 `VERIFIED`。

选择 MODEL 表示本次明确允许向已配置供应商发送问题、同一会话中本人提交的最多 4 条其他近期问题（派发时读取，不是本请求创建时冻结的会话历史）、快照中的最多 2 条目标和 2 条明确记忆摘要，以及可选本人提交的答案和分数。每条目标/记忆/近期问题最多取 500 字符，本人答案最多取 1000 字符；每条知识片段发出最多 1500 字符。上下文不读取或发送标准答案、隐藏测试、他人资料、先前模型答案或整个私人作品正文；API key 只用于所配置地址的认证 header，不进入模型提示或公共 DTO。完整快照的全部来源仍参与有效性检查和文档血缘。

| 当前运行约束 | 默认值与边界 |
|---|---|
| 并发与待办 | 每进程最多两个导师工作线程；每用户最多 4 个未终结请求，后者可配置 1–16 |
| 请求次数 | 每用户每天 100 个已接受请求，可配置；跨工作空间共用 UTC 日额度，取消不退次数 |
| HTTP 总超时 | 默认 20 秒，可配置 100–60,000 毫秒；不跟随重定向，只接受 HTTPS 或明确配置的 loopback HTTP |
| 请求绝对期限 | 创建后 120 秒，包含排队；证据 lease 为 15 秒，模型 lease 为 HTTP 超时加 15 秒，并受绝对期限约束 |
| 输入与输出 | 发出正文最多 65,536 UTF-8 字节，接收正文最多 131,072 字节；回答最多 12000 字符 |
| 模型输出 token | 默认 2048，可配置 64–8192 |
| 每日 token 额度 | 默认 1,000,000，可配置；按输入字节上限、协议余量和输出上限保守预留 |
| 安全恢复次数 | 尚未派发外部请求的工作最多领取 3 次；已派发结果未知时不盲重放 |

token 准入与供应商自报用量不是货币账单或模型质量测量。确认的 prompt/completion/total tokens 必须通过边界检查，并幂等结算到请求原来的 UTC 日期；已取消或跨午夜也不换账期。数据库等待和长 CPU 工作没有被包装成硬中断沙箱，但过期结果不得提交。

| `billingState` | 当前处理 |
|---|---|
| `NONE` | 证据模式，没有外部模型用量 |
| `RESERVED` | 已预留，尚未确认实际用量 |
| `RELEASED` | 明确尚未派发的请求取消、过期、缺配置或无证据，释放预留 |
| `SETTLED` | 供应商自报用量已确认并幂等结算；无效答案也不能假装没有消耗 |
| `UNKNOWN` | 已派发后超时、取消、崩溃或无法确认用量，保留预留，不自动重放 |

取消要求 `expectedEpoch` 并递增 epoch。相同取消可幂等重放；完成或其他终态不能被取消改写。迟到响应可以按原执行身份补记已确认用量，但不得恢复取消文本。恢复优先检查绝对 deadline，再检查 scope；禁用账户、归档空间、撤回上下文、失去配置及重试耗尽的候选会写入可解释终态，不能让旧队列头永久挡住健康空间。

内容已发送给供应商后，平台不能承诺供应商停止生成、删除已接收内容或退款。撤回阻止平台后续准入与展示；当前没有供应商 job 查询、自动退款或人工对账适配器。公共事件仅保存请求/作品 ID、状态和安全类别，不复制完整 prompt、凭据或供应商错误正文。

## 3. 保留的完整教学专家目标

以下是后续设计，不是当前固定导师 worker 的完成声明。需要接入分类、更多工具、独立事实评审与模型效果验收后，才能采用这些更丰富的教学路径；其中 2 次模型调用、一次格式修复等数字不替代上节当前实际配置。

1. 验证会话、正文长度（≤4000 字符）、当前 conversation 所有权；如带 attemptId，核对同一用户及 releaseId。
2. 分类为概念/签名比较/诊断/提示/复习；无关问题简短说明能力范围。分类失败使用保守的概念解释流程。
3. 从白名单端口读所需上下文，只传当前代码片段、诊断、concept 和 hintLevel；不发送其他学习者资料。
4. 检索 ≤8 条证据；过滤退役/未审核/错误版本；按问题需要补一条反例。保留检索原始集合供后处理核验。
5. 仅允许 `searchEvidence`、`getOwnAttempt`、`requestCompile`、`listRelatedExercises`。编译工具也走隔离队列；禁止任意 URL 和调用字符串拼接。
6. prompt 由系统规则、任务、引用片段、不可信用户输入分区。一次局部短问答最多 2 个工具调用、2 次模型请求，输入上下文上限 12000 tokens，输出上限 1500 tokens；由服务端硬限制。多作品任务改由 M13 划分专家节点、共享运行预算并跟踪完成条件，不套用短问答的整任务上限。
7. 将响应解析为严格 JSON；无效结构最多修复 1 次，仍错返回可读失败。核验引用 ID 属于本次证据、推荐题存在同发布、诊断与 sourceHash 一致。引用存在不等于支持论断，人工评测仍要判断蕴含关系。
8. 保存 promptVersion/model/releaseId/latency/usage/status；只把完成且通过结构验证的响应标记 COMPLETED。模型超时 30 秒，整请求 45 秒起始预算；上游已开始生成时不自动盲目重试。

## 4. 提示阶梯与学习证据的目标

当前 MODEL 的 Java 系统提示把 0–4 分别表达为引导性问题、概念提示、规则解释、相关例子、详细讲解；模型遵从率尚未实测，EVIDENCE_ONLY 按级别选择不同的学习提问，课程原文保持可核对。两种模式都不读取隐藏标准答案，第 4 级也不额外授予该权限。M05 现有独立的题目提示接口，最多三级并真实记录 assisted；不能把导师 hintLevel 参数当成该客观提示账本。不能仅凭保存作品认定独立掌握，首次题目家族样本规则仍由 M05/M06 执行。下面更丰富的提示教学效果仍需评测。

| 级别 | 内容 | 学习记录 |
|---|---|---|
| 0 | 学习者独立预测/回答 | 可参与独立掌握度 |
| 1 | 指向概念与一个反问 | 记录已使用概念提示 |
| 2 | 指出错误行与相关边界 | 记录定位提示 |
| 3 | 给局部签名或骨架，保留关键空缺 | 记录补全提示 |
| 4 | 用户明确请求后展示完整解答与解释 | 不计作独立答对 |

目标是让模型不跳级，并把实际提示使用同步到学习记录；不能把提示词中的要求冒充已经测得的模型行为。当前接口对所有级别都隔离标准答案和隐藏测试。

## 5. 当前异常处理与后续工具安全

下表中的编译工具、标准答案专项检测和流式传输是完整教学目标；当前 MODEL 为非流式请求，已有执行行为以第 2 节为准。资料中的指令不能获得当前根本未开放的工具权限。

| 场景 | 行为 |
|---|---|
| 检索无命中/证据不足 | 返回已有概念入口与不足说明，不能编造引用 |
| 用户要求忽略规则或资料内含命令 | 当作普通文本，不执行；继续限定工具 |
| 编译结果与模型解释矛盾 | 保留编译事实，标记解释待核查，不覆盖判分 |
| 模型断开/限额用尽 | 阅读、练习、检索继续工作；MODEL 请求显式失败，证据模式不伪装成模型回退 |
| 流式传输断开 | 通过 requestId 恢复状态；中间 token 不计作最终结论 |
| 引用不存在/标准答案泄露 | 阻断展示并记错误类别，返回受控失败 |
| 恶意 Markdown/代码块 | 前端渲染净化且代码转义，不运行 HTML |
| 上游日志/数据留存 | 接入前核实供应商设置；当前 MODEL 明示分享范围见第 2 节，不能承诺撤回已发数据 |

## 6. 实际验证与模型效果评测目标

当前专属测试 `TutorRuntimeTest`、`TutorHttpProviderTest`、`TutorHttpBoundaryTest` 使用真实 SQL、真实 loopback HTTP 协议夹具及 HTTP/schema/CSRF 边界，覆盖幂等、跨用户引用、取消、恢复、UNKNOWN 额度、撤回、严格输出和回答转文档。具体运行结果见 [本轮验收](../evidence/runtime-review.md)。这些测试不证明某个外部供应商已经兼容，也不证明模型事实正确、提示遵从或教学有效。

保留独立的开发集与验收集，禁止用验收问题原文作为提示模板。最终 ≥50 案例：概念 10、代码解释 10、错误诊断 10、分级提示 8、无证据/越界 6、注入/隐私/失败 6。现有 `agent/evaluation-cases.json` 是起始设计集，actual/status 明确未运行。

每例评价：事实正确 0–2、必要边界 0–2、证据支撑 0–2、教学帮助 0–2、任务遵从 0–2；两人独立评分、争议回查规范。严重错误（编造编译结果、泄露他人记录、虚假引用）单列，不被平均分掩盖。

内部发布目标：关键泛型事实正确率 ≥95%，引用 ID 有效率 100%，引用支持率 ≥95%，保留的安全负例无越权，分级提示遵从率 ≥95%。需报告样本量、失败题、模型版本、温度、运行日期、重试策略与花费；当前不能宣称这些数值已达到。

## 7. 真实端口与后续工具契约

`KnowledgeRetriever` / `LocalKnowledgeSearch` 提供实际版本化检索，导师使用带 contentHash 的 `EvidenceView`。`TutorAnswerProvider.Prompt` 明确区分问题、近期用户问题、本人上下文及证据；`Answer` 包含文本、引用、限制、供应商自报用量与模型标识。HTTP adapter 负责有界传输和严格结构解析，`TutorService` 负责归属、状态、租约、额度及再次验证。模型调用以 `TutorAnswerProvider` 为真实端口。

`CompilationGateway` 及未来的诊断、练习推荐工具仍是边界设计；不可信源码不得在 API JVM 中编译或执行。模型适配器不能接管课程规则、客观评分或发布权限。
