# 工作空间状态与跨模块交互协议

本章把学习、练习、Agent、作品与记忆之间的联动收敛为可实施的状态协议。它是前端后续开发的约束，不表示已经实现网页、SSE、离线缓存或浏览器验收。机器可读的设计摘要在 [state-contract.json](../frontend/state-contract.json)；业务请求和响应以 [OpenAPI](../contracts/openapi.json) 为准，不把本章的客户端视图字段直接发送给服务端。

核心原则是：学生可自由组织工作空间，服务端事实负责驱动联动；一个页面不能凭动画结束、模型措辞或另一个组件的本地状态改变成绩、作品审核结果和费用。

## 1. 状态所有者

| 状态层 | 内容 | 写入者 | 生命周期与边界 |
|---|---|---|---|
| 服务端事实 | 题目版本、提交、评分、运行、作品revision、学习投影 | 对应业务服务 | 客户端只接收有版本的快照；不同模块不互相改写主数据 |
| 待确认命令 | 幂等键、操作名、输入快照、预期版本、发送结果 | 客户端命令协调器 | 成功后对账；超时是结果未知，不是未执行 |
| 本地草稿 | 代码、文案、布局、未提交选区、失败输入 | 学生的编辑操作 | 按用户、工作空间、资源、基础版本隔离；绝不被后台事件直接覆盖 |
| 瞬态交互 | hover、焦点、面板宽度、拖动预览、菜单 | 当前视图 | 卸载即释放；不写入长期记忆；拖动每像素不调用模型 |
| 能力与偏好 | 可用模块/工具、自主程度、主题、动效、预算上限 | 服务端能力和已保存偏好 | 禁用能力不能被模型重新开启；客户端不能自授权限 |
| 连接与验证 | 同步状态、序号缺口、过期、审核、错误 | 数据协调器和服务端事实 | 与业务运行状态分开，例如作品已保存仍可能未通过核验 |

实现时以实体索引和查询缓存持有事实，编辑器独立持有草稿；不把所有数据放进一个任意可写的全局对象。跨模块事件只使相关查询失效或应用完整、经过校验的快照，禁止组件 A 直接调用组件 B 的 setter 传递业务事实。

## 2. 实体版本与作用域

客户端缓存键至少带当前身份作用域、workspaceId、releaseId、资源种类、资源ID。知识与题目附revision，Agent附runEpoch/planRevision；值为null的作用域不能被当成通配授权。

| 资源 | 已有契约字段 | 拒绝应用的情况 |
|---|---|---|
| Workspace | id、releaseId、revision、eventSequence | 旧工作空间响应；revision小于已接受值；来源身份已失效 |
| AgentRun | id、workspaceId、snapshotId、runEpoch、planRevision、steps | 旧epoch；同epoch旧planRevision；越工作空间结果 |
| RunEvent | 请求路径中的runId、sequence、type、payload、createdAt | 重复序号、缺口后的孤立事件；不能仅凭payload文案更新作品或分数 |
| WorkspaceEvent | id、workspaceId、sequence、revision、type、origin、occurredAt、data | 越空间事件、序号缺口、已失效的身份；不能把事件revision直接当作作品revision |
| Artifact | id、workspaceId、currentRevision | 较旧revision，或资源已离开授权范围 |
| ArtifactRevision | artifactId、revision、contentHash、reviewStatus、inputRefs | 哈希/版本不一致；引用已失效；不能自动覆盖不同baseRevision的草稿 |
| Attempt | id、releaseId、exerciseId、exerciseRevision、status、hintLevel | 不同题目/发布；尚未GRADED却带“答对”显示；FAILED被记为学生错误 |

`AgentRun` 没有顶层 releaseId，客户端从其 workspaceId 对应的已授权 Workspace 解析固定发布；上下文引用字段为 snapshotId，节点列表为 steps，不使用旧草案中的 contextSnapshotId/stepStates。各 revision 与 epoch/sequence 的数值上限按 OpenAPI 校验，不能截断或四舍五入超范围值。

`RunEvent` 的 payload 与 `WorkspaceEvent` 的 data 是事件数据，不是完整实体快照；不存在统一的 resourceIds 字段，也不保证每种事件都带 epoch 或所有事实版本。收到事件后按受支持的 type 和允许字段定位受影响查询，再重新读取授权快照；未知事件只触发保守刷新，不解析文案为业务命令。将来扩展为完整投影事件时，先同步服务端、OpenAPI、重放测试和消费者。

切换用户、工作空间或内容发布时递增本地请求代号并中止旧请求/订阅。即使网络取消未成功，返回时仍核对代号与作用域。退出登录清除私有内存缓存和待授权操作；持久草稿恢复必须重新登录同一用户，不能展示给下一位使用者。

## 3. 序号与断线恢复

事件游标按每个流单独保存：运行流用 runId，已实现的工作空间流用 workspaceId。当前两者都有受授权的真实轮询接口；SSE 与前端消费器尚未实现。不同流的 sequence 不能比较，不设置全站“最大已见序号”。只在事件被正确处理并记录投影后推进本地游标；服务端投影的新鲜度可读取工作空间 projection。

1. 初次进入先取资源快照。订阅建立与快照之间存在竞争时，用服务端提供的一致快照游标补齐事件；若契约没有该游标保证，则事件只负责触发再次取快照。
2. 以 `after` 与 `limit` 分页读取 `/agent-runs/{id}/events` 或 `/workspaces/{id}/events`；对应操作分别为 listRunEvents 与 listWorkspaceEvents，以当前 OpenAPI operationId 为准。重复事件忽略；连续序号才推进本地游标。
3. 收到缺口或分页顺序异常时，将该流标为`RESYNCING`，保留当前画面并显示正在同步；补页或重新取快照，不能跳过缺口把后续状态当完整事实。
4. 当前日志没有自动保留期清理承诺；未来启用清理时，必须同时实现过期游标的明确冲突响应和快照恢复。届时重取当前快照并重建订阅，不得无限重试过期游标或在服务端未定义时假造恢复保证。
5. 网络恢复先查询待确认命令是否已经创建对应资源，再恢复轮询/日志；相同输入重试复用同一幂等键。付费生成、评分和导出不能在每次重连时创建新任务。
6. 未来SSE只改变传输方式。`Last-Event-ID`必须映射到同一持久流及授权上下文，日志去重和重放规则保持一致。当前未实现SSE时使用真实分页/轮询，不返回假实时更新。

未知完成比例显示“已完成2项，另1项等待输入”等可证明事实，不显示线性增长的伪百分比。自动滚动仅在用户已处于列表底部时执行；阅读历史或编辑代码时，新事件显示计数提示而不抢焦点。

## 4. 命令确认与人工编辑

客户端命令视图状态为`DRAFT → SENDING → ACKNOWLEDGED / UNKNOWN / REJECTED`。这是客户端状态，不新增后端枚举。服务端返回202只表示已接受作业，不能立刻变成“已生成”。`UNKNOWN`保留幂等键、输入和时间，供重查；网络超时后不要用新键重发。

| 操作 | 可否乐观预览 | 提交与失败行为 |
|---|---|---|
| 切换主题、展开面板 | 可以 | 偏好保存失败显示未同步；恢复最后确认值或保留明确本地值 |
| 拖动作品元素、编辑文案 | 可以，仅当前草稿 | 保存带baseRevision；409保留草稿与服务器版本，展示差异或另存副本 |
| 提交答案、编译、Agent生成、导出 | 只显示已发送/等待确认 | 以服务端资源状态推进；不预写分数、成本或作品审核结果 |
| 暂停、取消、改变目标 | 只显示请求处理中 | 带expectedPlanRevision/expectedRunEpoch；服务器确认前不能声称已停止扣费或旧结果已取消 |
| 删除、撤回记忆 | 可隐藏但保留恢复入口 | 服务端成功再终结；失败恢复条目；不可用动画假装已删除 |

学生保存revision N+1后，仍基于N的Agent输出只能成为待比较候选；服务端必须拒绝旧baseRevision覆盖。前端不能用“AI已完成”弹窗压掉人工编辑。局部生成明确scope、引用快照和允许修改的对象，修改目标后由新epoch接续，旧事件只能用于历史审计。

编译结果绑定提交时的源码哈希。学生继续编辑后，旧结果显示“对应上一版本”，运行按钮可再次发起；不能把上一版通过标记贴在新源码上。类似地，知识结论改变会使依赖作品进入STALE，改颜色只使布局/渲染依赖失效，不能重置已经成立的学习成绩。

## 5. 需要可操作的五条联动

| 起点 | 中间事实 | 受影响视图 | 可核验的完成条件 |
|---|---|---|---|
| 阅读后请求解释 | 概念/发布/选区组成上下文快照 | 指导栏、引用抽屉、相关练习 | 回答引用同一版本；撤回选区后不继续使用旧内容 |
| 预测并提交泛型代码 | attempt→编译证据→客观判分 | 结果、错题、掌握度、下一步建议 | 同一attempt只计一次；基础设施失败不扣学生成绩 |
| 三错题制作互动册和PPT | 固定错题证据→计划→候选作品→核验 | 运行条、作品树、画布 | 每种作品有独立revision和审核状态；部分失败仍可打开已完成内容 |
| 学生修改作品的事实 | 新revision→依赖失效通知 | 文档/PPT/视频脚本/导出 | 过期标记可解释；只重做受影响部分；人工文本不被旧worker覆盖 |
| 复练与撤回记忆 | 独立复练事实/记忆授权变化 | 复习队列、知识图、后续上下文 | 提示后作答不等于独立掌握；撤回记忆不再注入新快照 |

这五条是前端和后端的共同验收场景；目前设计存在，不意味着浏览器链路已经完成。后端已有的可执行验证范围应从实际测试报告读取。

## 6. 状态必须保留语义区别

数据视图至少区分`LOADING / READY / EMPTY / STALE / OFFLINE / FORBIDDEN / NOT_CONFIGURED / FAILED`，不得把所有非成功情况渲染成空白。

- EMPTY只用于成功查询且确实无记录；服务器500/503显示FAILED及重试。
- FORBIDDEN不暴露别人的资源标题或内容；可以返回不泄漏存在性的404。
- NOT_CONFIGURED用于模型/媒介适配器未配置。显示具体缺少的能力、可继续使用的功能，不出现模拟模型答案。
- STALE保留旧内容并标注对应版本；不继续显示“已核验”。
- OFFLINE保留可见内容和本地草稿，禁用需要远端授权的执行；不把本地保存标为已同步。
- 内容审核、工具运行、作品保存、引用有效性分别显示。schema通过、文件导出成功、模型称“检查完成”都不能单独产生VERIFIED。

错误保留code与traceId供问题反馈，向学生展示可理解的动作；不返回供应商密钥、私有系统提示词或堆栈。toast只补充结果，字段错误和版本冲突必须留在原位置。

## 7. 可生成的交互界面

Agent只能提出已登记的作品DSL和业务动作。前端使用显式组件注册表渲染允许的kind/block/action；未知schemaVersion或不支持类型显示可恢复说明，不执行模型生成的JS、脚本HTML、动态import、任意工具名或外链。

流式文字允许逐段展示，但半截JSON不挂载成可交互卡片。完整候选先通过schema、资源归属、引用版本和业务动作校验，再呈现。导出预览、工具日志和参考文档属于不可信内容，不能改变系统权限、预算或指令来源。

状态线显示“检索泛型边界资料”“验证反例”“等待你选择微课长度”等工作事实；不要求或展示模型的内部思维链。每项建议提供理由依据与可拒绝入口，学习者可以关闭持续建议而继续手动使用平台。

## 9. 键盘、移动与动效

桌面保留可收起的作品树、画布、指导栏；窄屏一次只聚焦一个视图，切换后保存草稿和滚动位置。手机软键盘打开时输入栏不得挡住发送、取消和当前文本；留出安全区，避免全屏固定高度导致中文候选栏遮挡。所有拖拽、滑动、长按都有按钮或键盘替代，焦点不会因任务更新跳到后台面板。

主题、字号、对比度和reduced-motion遵循用户偏好。系统减少动效或用户关闭动画时，停止粒子、呼吸、自动轮播和弹簧循环；保留直接可见的状态变化。动效不可作为完成判据。组件卸载清理timer/rAF/observer、订阅和媒体对象URL；拖动结束才提交持久变化。

## 10. 实施后的验收清单

前端实现时必须在真实浏览器覆盖：重复事件不重复加分；事件缺口触发重同步；旧epoch不覆盖新任务；workspace切换后的慢响应被丢弃；发送超时重连不重复付费；保存409不丢草稿；基础设施失败不记答错；模型未配置有明确状态；注销不显示前一用户缓存；无动画、320/768/1440宽度、中文输入法、软键盘、键盘焦点和触屏可以走完同一业务链。

验收证据应包含输入、响应、事件序号/版本、操作截图或录屏、失败重现和实际测试结果。只通过JSON语法或后端单元测试不能将以上浏览器项目标为PASS。
