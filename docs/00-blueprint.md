# 泛型工坊：整体框架与评分映射

版本：持久化学习运行时 v0.3；日期：2026-11-13。课程知识主线为第 17 个知识点“泛型与类型安全”；创作媒介、学习路线和专家协作方式保持高自由度。

本章的产品场景和模块表描述完整目标。当前已经实现认证、发布内容读取、BM25、选择题判分、工作空间/记忆、事件投影、作品源版本及持久任务控制；正式前端、LLM 规划/导师、编译沙箱、媒体生成、导出与正式审核发布仍不可用。逐模块与逐操作状态以 [contracts](../contracts/README.md) 为准，实际验证见 [v0.3 验收记录](../evidence/runtime-review.md)。

## 1. 需求边界

课程要求建设交互式智能学习网站，必须有独立知识库、数据库、Java/Spring Boot 后端、实际前端和与主题相关的智能助手。课程建议 Vue 3，但允许其他合理前端。本项目选择 React + TypeScript，以便直接研究用户参考文档中的 TSX 交互机制。

用户此次要求：两个人完成完整职责；先交付详细框架和模块实现方式并同步 GitHub；前端暂不实现，重点给出样式和交互规范；提交前检查设计、联动、传输、安全、稳定性、效率和知识正确性。用户已确认教师认可两人组，因此不把原文的三人要求当作当前阻塞条件，也不虚构第三位成员。

用户追加的核心方向：以超级 Agent 集群贯穿学习全过程，支持 PPT、文档、图片、音频、视频和高交互错题集，提供个性化深度指导。本设计已纳入主线；通过工作空间语义事件持续接续，可选择按需/协作/安静模式，不采集站外活动。三个项目的实际借鉴见 [研究记录](12-reference-research.md)。

## 2. 产品定位

面向已学过类、接口与集合的 Java 初学者，解决四个问题：能写出 `<T>` 但不知道约束；误以为 `List<Integer>` 可以当 `List<Number>`；机械背诵 PECS；能看模型答案却无法解释编译器为什么拒绝。

完整目标场景：学生提出“把我的三道 PECS 错题变成互动错题集、8 页 PPT 和两分钟微课” → 专家集群读取本人学习事实 → 并行核查知识、代码和教学结构 → 生成共享证据的多种作品 → 检验事实、交互和渲染 → 学生局部修改或继续提问 → 新变式上的独立作答反馈到后续计划。普通概念问题走短路径，无需每次启动所有专家。当前可运行到客观作答、学习投影、本地证据检索工作流与错题/作品源稿；完整多媒体场景不是当前完成声明。

主要用户为学习者；课程编辑负责知识与题目；项目维护者负责发布、运行和评测。编辑与维护者可由同一真实成员兼任，但权限设计区分三类角色。

| 演示与答辩 | 10 | 10 | 10–15 分钟演示，两人都能讲整体并现场修改/解释自己的关键代码 |

## 5. 完整课程范围

16 个概念单元：类型参数动机、泛型类、泛型接口、泛型方法、类型推断、不变性、上界、多重边界、无界通配符、extends、super、PECS、捕获、类型擦除与桥接、可具体化类型与数组、原始类型/堆污染/泛型可变参数。

8 类实验：①容器赋值是否合法；②读写能力矩阵；③类型边界拼装；④泛型方法推断；⑤通配符捕获修复；⑥擦除前后/桥接方法观察；⑦原始类型安全重构；⑧综合 API 签名设计。每类需有正例、反例、边界例和讲解依据。

最终内容目标（尚未完成）：至少 64 张经人工审阅的知识卡、48 组可核验示例、120 道去重题目、40 个检索金标准与 50 个 Agent 测试。数量只是覆盖规划，发布必须满足概念×题型×难度覆盖与正确性；不得为达到数量重复改名。当前 `demo` Profile 提供 16 个概念、16 张原创知识卡、12 道客观题，并保留固定泛型编译验证样例。演示内容标明 `origin=demo-authored-code-reviewed`，不冒充正式双人审核；历史 SQL 种子仍为草稿。

## 6. 分阶段边界

- **本次 v0.3**：可审阅设计、持久化学习运行时、真实 SQL/HTTP 应用链、确定性本地检索工作流、固定语义案例、前端状态协议及检查记录；没有正式前端或外部智能/媒体能力。
- **P0 可运行纵向闭环**：原课程功能＋工作空间/目标/快照＋可中断任务图＋有真实复练的交互错题集＋文档/PPT源作品，先证明复杂学习任务贯通。
- **P1 用户要求的完整创作范围**：图像、音频、视频、各类导出、局部重做、版本传播、个性化记忆、完整八类实验和量化评测。音视频属于基础闭环之后的必做范围。
- **P2 可选增强**：向量混合检索、教师观察台、更多模型/媒介适配器、多人协同编辑。只在 P0/P1 证据通过后开展。

当前能力状态由契约和 `/api/v1/capabilities` 显式标记；未来前端不得展示未落地能力为“可用”。最终八类成果与实际文件映射见 [协作计划](09-team-plan.md)及[课程交付验收](16-course-delivery.md)。
