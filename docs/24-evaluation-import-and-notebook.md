# v0.6 评测、批量加工与六类错题交互

本章记录已经进入代码、契约和页面的新增业务边界。运行结果与环境以[当前验收](../evidence/runtime-review.md)为准；实际请求和 DTO 以 [OpenAPI](../contracts/openapi.json) 为准。新增能力是 `EVALUATION_WORKBENCH`、`BATCH_INGESTION`、`CONTENT_REVISION_DIFF`、`TEXT_GRADING`、`NOTEBOOK_INTERACTIONS`。模型和独立编译 worker 仍分别按部署配置开放。

## 1. 私有检索评测工作台

每个评测套件属于真实会话所有者及一个固定课程的工作空间。套件含 1–40 个案例，案例选择概念过滤、查询文本及预期证据；预期知识卡必须属于该发布。`MATCH` 选择 1–8 个不同知识卡；`NO_RESULTS` 必须没有预期卡。同一概念过滤下的重复查询不能用来扩大样本数。预期标签由套件所有者填写，界面和报告明确这一事实。

编辑采用 `expectedRevision` 比较并追加不可变版本。每版保存查询、标签、知识卡版本、来源定位、发布 manifest hash、corpus hash 和检索算法版本。历史运行固定旧版本，新修订不会重新解释旧结果。当前私有评测不提供多人协作编辑或个人贡献认定。

运行由服务端持久队列启动，浏览器没有提交自拟结果的完成接口。实际执行调用当前 BM25 检索器，逐案例保存排序、相关性、来源、耗时和结果 hash；取消保留已经完成的案例，只有全部完成才产生汇总和下载报告。报告同时包含 suite ID、suite revision、原始定义、语料清单、指标公式、逐项结果和限制说明。

| 指标 | 精确定义 |
|---|---|
| Precision@K | 命中的预期知识卡数 / 请求的 K；缺少的返回排名记为不相关 |
| Recall@K | 命中的预期知识卡数 / 本案例预期知识卡总数 |
| MRR | 首个相关结果的排名倒数；无命中记为 0 |
| Hit rate | MATCH 案例中至少命中一个预期卡的比例 |
| No-result accuracy | NO_RESULTS 案例中确实返回空列表的比例 |
| 通过案例 | MATCH 的所有预期卡都被返回，或 NO_RESULTS 确实为空 |
| 耗时 | 当前运行单调时钟的实测时间；不外推生产 P95 或吞吐量 |

前四项仅在 MATCH 组内宏平均；没有对应组时指标返回 `null`。评测不产生 `ATTEMPT_GRADED`，不更改学生成绩、掌握率或贡献数据。下载为实际 JSON 附件，鉴权、内容 hash、声明字节数及套件元信息会再次校验。

### 资源与恢复边界

| 资源 | 当前上限 |
|---|---|
| 套件与修订 | 每账户 30 个套件（含归档），每套件 100 个修订 |
| 定义体积 | 单版含语料清单 256 KiB；每账户累计 32 MiB |
| 本地评测语料 | 512 张已发布知识卡、正文合计 1 MiB |
| 每次运行 | 40 个案例；K 为 1–8；实际执行最多 60 秒 |
| 队列 | 每账户最多 2 个未终结运行；全局 64 个；单 CPU 工作线程 |
| 历史与日准入 | 每账户保留 200 次运行；每 UTC 日最多新增 20 次 |
| 中间结果与报告 | 单案例 64 KiB，单次案例结果累计 1 MiB，完整报告 2 MiB；账户累计 64 MiB 并包含未完成预留 |
| 过期与恢复 | 队列等待超过 10 分钟失败；90 秒租约自然失效后明确失败，不将中断记为完成 |

停用账号、归档空间或归档套件会阻断新执行和迟到提交。所有权锁、空间锁、套件锁、运行锁顺序一致。对外轮询只读取该次元信息公布的已提交结果前缀，避免下一案例并发完成时产生错误的完整性冲突。语料或算法变化会拒绝复用旧套件快照。

## 2. 有界批量资料导入

编辑者先登记来源，再选择 1–8 个文件。支持严格 UTF-8 TXT/Markdown，以及 DOCX 主体和表格文字。解析不下载来源 URL、不访问 DOCX 外部关系、不读取本机路径、不执行宏。PDF、扫描件、旧 DOC、宏文档明确不支持；包含多分支 `AlternateContent` 的文档明确拒绝，避免把兼容分支正文重复采入。未接受/拒绝的 Word 修订和移动记录也明确拒绝，防止把移动前后的内容同时采入。图片、批注、脚注和样式不在正文提取范围，界面要求人工核对。

文件大小每个 1 MiB、每批合计 4 MiB；两个并发准入许可覆盖上传流读取、hash、解析和入库全过程，忙时在复制文件到应用内存前返回 503。DOCX 最多 128 个部件、2 MiB 解压数据、100 倍压缩比例、64 层主体 XML 深度，并有 2 秒解析预算。禁止 DTD、外部实体、宏、ActiveX、嵌入程序、路径穿越和重复压缩部件。ZIP 不会解压到文件系统。

逐文件结果独立：健康文件为 `READY`，失败文件保留稳定错误码和可理解的说明。原文最多 32,000 字符，清洗稿最多 16,000 字符；超过清洗稿上限时留空等待编辑，不能截断后宣称完整。BOM 和换行统一，Java 代码缩进保留。原始二进制不持久保存，但上传 SHA-256 与提取文字 SHA-256 分开记录。

用户显式选择健康项并确认，服务端才在一个事务内调用现有人工采集服务，生成原稿、清洗稿、处理说明及来源 hash 收据。任何条目出错，所有选中项一起回滚。它不自动生成知识卡、审核或发布课程。重复的来源、原稿 hash、清洗稿 hash 复用经过完整性验证的既有收据。

每账户最多 3 个待确认预览、滚动 24 小时最多创建 100 批；预览有效期 24 小时。提交、取消、过期和账号关闭都清除暂存原文与清洗稿，终态保留上传元信息与真实 capture ID。提交后的正文保存在不可变采集收据中，仍归属于原作者。版本号与幂等键保护重复请求及“提交/取消”竞争；其他编辑也不能读取私人预览。

## 3. 内容修订差异

`GET /admin/content-diffs` 对同一知识或练习的两个修订做只读比较，要求当前有效的 EDITOR/ADMIN 角色。先重读并验证两个版本的内容与来源完整性，再生成稳定排序的 JSON pointer 字段路径。对象逐字段比较，数组整体比较以保留顺序含义；缺失值用 `null` 表示，变化种类为 `ADDED`、`REMOVED`、`CHANGED`。

版本、作者、审核状态和时间不冒充正文修改。审核 hash 和状态在比较头部单独显示。答案及 rubric 的差异仅对编辑开放，学习者接口仍只投影公开字段。比较深度 24 层、最多 256 处变化、响应 1 MiB；超过时要求分别查看原修订，不截断后声称完整比较。保存和独立审核面板均可选择真实历史版本比较。

## 4. 有独立审核凭证的短文本判分

READING/DIAGNOSIS 题可声明 `answerKind=TEXT`。编辑私有规则 `text-exact-nfkc-v1` 包含有限的接受/拒绝答案及适用范围；每组 1–16 条，规范化后不得重合。算法做 NFKC 规范化、Unicode 空白折叠及可选的不区分大小写，再对完整字符串精确比较。标点和词序保留，不用关键词包含或模糊相似度猜测理解程度。

作者之外的编辑批准时保存完整答案 JSON hash 的独立审核收据。发布和实际判分均核对收据及原规则；单独伪造一个 `REVIEWED` 状态不能启用 TEXT 判分。学习者只能看到规则适用范围、字符/UTF-8 字节限制和规范化方式，看不到接受答案、拒绝答案或审核人信息。结果为真实 0/100，不声称开放自然语言语义判分。

TEXT 与 CHOICE/CODE 进入同一个 attempt、outbox、独立题族证据、辅助标记及复习流程。领取提示、重复作答或同题族反事实练习不能产生新的首次独立样本。Notebook 调用相同服务，历史原题版本和首次答错事实不会被修订覆盖。

## 5. 六类错题块

从真实错误或受助作答构建 ERROR_CONTEXT。后续通过当前原始块的 `block-options` 发现合法候选，并显式追加新块；服务端派生题目、概念、来源和动作白名单。每次追加保存新的不可变作品修订，不改写旧稿。新稿的交互状态从 0 开始；状态严格绑定 artifact ID、artifact revision、block ID 和 state revision。

| 块 | 实际动作与结果 |
|---|---|
| ERROR_CONTEXT | 预测、证据、CHOICE/CODE/TEXT 原题复练、三级提示；代码原题按部署能力提交编译 |
| TYPE_FLOW | 选择真实有限类型及参数，调用 LabService 的赋值/读写规则，保存预测与实际结论 |
| REPAIR_DIFF | 从实际原始代码和修改代码分别创建两个编译作业，展示各自状态及诊断；最终提交仍用原题判分规则 |
| COUNTERFACTUAL | 只选择同发布、同题族、已审核的真实题目版本，持久保存选择，再调用原判分与提示服务 |
| EXPERT_HELP | 调用真实逐层提示服务；每次动作按当前版本和状态校验，帮助记录进入受助规则 |
| REVIEW_LINKS | 选择当前空间的真实复习/作品候选，导航前重新核对允许列表、作品当前版本与完整来源闭包 |

六种块只接受对应白名单动作。迟到状态、旧作品修订、其他用户/空间、已经撤回的来源或伪造候选都被拒绝。读取恢复真实选择和提示层级，动作有幂等回执；探索行为不自动记成成绩。当前不生成未经审核的反事实变式，不执行任意用户程序，也不把静态导出的 HTML 记作线上学习证据。

## 6. 前端与检验落点

知识页增加基于真实前置关系的分层路径和文本导航，阅读活动与独立学习证据分别呈现。评测套件、资料清洗稿及内容修订均保存独立编辑草稿；刷新事实和任务轮询不能覆盖输入。提交时有局部进度、错误和恢复入口，冲突保留草稿；终态或版本变化时停止相应编辑/轮询。

浏览器验收启动独立数据库，按每次运行随机生成两位仅用于测试的编辑账户和一位管理员；账户先经真实注册成为学习者，再通过正式启动配置赋权并真实登录，独立审核走实际 API 与页面。测试不读取生产凭据，不伪造正式人类审核。H2 全量回归、真实 MySQL 服务/约束、HTTP 重启、DOM 联调及远端 Chromium 分别出具证据。测试成功不能证明供应商教学质量、生产压力或最终课程答辩完成。
